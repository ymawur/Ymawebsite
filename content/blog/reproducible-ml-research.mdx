Reproducibility is a cornerstone of scientific research, yet it remains a significant challenge in machine learning. This post outlines best practices for making your ML experiments reproducible, from code organization to experiment tracking and documentation.

## Why Reproducibility Matters

Reproducibility ensures that:

- Other researchers can verify and build upon your work
- You can debug issues and iterate on experiments
- Results are not due to random chance or implementation errors
- Your work has lasting scientific value

<Callout type="warning">
  A 2016 study found that only 6% of ML papers provided code, and even fewer provided data and
  environment specifications. This makes independent verification nearly impossible.
</Callout>

## Code Organization

A well-organized codebase is the foundation of reproducible research:

```
project/
├── configs/           # Configuration files
│   ├── experiment1.yaml
│   └── experiment2.yaml
├── data/             # Data directory (not in git)
├── models/           # Saved model checkpoints
├── notebooks/        # Jupyter notebooks for analysis
├── src/              # Source code
│   ├── data/
│   ├── models/
│   ├── training/
│   └── evaluation/
├── tests/            # Unit tests
├── requirements.txt  # Python dependencies
├── environment.yml   # Conda environment
└── README.md         # Documentation
```

### Configuration Management

Use configuration files to track hyperparameters and experimental settings:

<CodeBlock>
{`# config.yaml
model:
  name: resnet50
  num_classes: 10
  pretrained: true

training:
  batch_size: 32
  learning_rate: 0.001
  epochs: 100
  optimizer: adam
  scheduler: cosine

data:
  dataset: cifar10
  train_split: 0.8
  augment: true

seed: 42`}
</CodeBlock>

<CodeBlock>
{`import yaml
from dataclasses import dataclass
from typing import Dict, Any

@dataclass
class Config:
    model: Dict[str, Any]
    training: Dict[str, Any]
    data: Dict[str, Any]
    seed: int

    @classmethod
    def from_yaml(cls, path: str) -> 'Config':
        with open(path, 'r') as f:
            config_dict = yaml.safe_load(f)
        return cls(**config_dict)

# Usage
config = Config.from_yaml('config.yaml')
torch.manual_seed(config.seed)`}
</CodeBlock>

## Random Seed Management

Control all sources of randomness:

<CodeBlock>
{`import torch
import numpy as np
import random

def set_seed(seed: int):
    """Set random seeds for reproducibility."""
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
    # For deterministic behavior (may impact performance)
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False

set_seed(42)`}
</CodeBlock>

<Callout type="info">
  Note that full determinism may come with a performance cost. Document when you use
  non-deterministic operations and their impact on results.
</Callout>

## Experiment Tracking

Use experiment tracking tools to log hyperparameters, metrics, and artifacts:

<CodeBlock>
{`import wandb

def train(config):
    # Initialize experiment
    wandb.init(project='my-project', config=config)

    model = create_model(config.model)
    optimizer = create_optimizer(model, config.training)

    for epoch in range(config.training.epochs):
        train_loss = train_epoch(model, optimizer)
        val_loss, val_acc = validate(model)

        # Log metrics
        wandb.log({
            'epoch': epoch,
            'train_loss': train_loss,
            'val_loss': val_loss,
            'val_acc': val_acc
        })

    # Save model artifact
    torch.save(model.state_dict(), 'model.pt')
    wandb.save('model.pt')

    wandb.finish()`}
</CodeBlock>

## Environment Specification

Document your computational environment:

### Requirements File

```bash
# Generate requirements
pip freeze > requirements.txt

# Or use pip-tools for better dependency resolution
pip install pip-tools
pip-compile requirements.in
```

### Docker

For maximum reproducibility, use Docker:

```dockerfile
FROM pytorch/pytorch:2.0.0-cuda11.7-cudnn8-runtime

WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt

COPY . .
CMD ["python", "train.py", "--config", "config.yaml"]
```

## Data Versioning

Track your data alongside your code:

<CodeBlock>
{`# Using DVC (Data Version Control)
# Install: pip install dvc

# Initialize DVC
dvc init

# Track a dataset
dvc add data/dataset.csv

# Push to remote storage
dvc remote add -d myremote s3://mybucket/dvc
dvc push

# To reproduce:
git checkout experiment-branch
dvc checkout  # Restores the exact data version`}
</CodeBlock>

## Documentation

Good documentation is essential for reproducibility:

1. **README**: Installation, usage, and expected results
2. **Code comments**: Explain non-obvious decisions
3. **Experiment logs**: Record what you tried and what worked
4. **Paper appendix**: Include implementation details

<Callout type="success">
  Consider using tools like Sphinx or MkDocs to generate documentation from docstrings. This keeps
  documentation in sync with code.
</Callout>

## Testing

Write tests to catch bugs early:

<CodeBlock>
{`import pytest
import torch

def test_model_forward():
    model = create_model(num_classes=10)
    x = torch.randn(2, 3, 224, 224)
    out = model(x)
    assert out.shape == (2, 10)

def test_data_loading():
    dataset = create_dataset(split='train')
    x, y = dataset[0]
    assert x.shape == (3, 224, 224)
    assert isinstance(y, int)

def test_reproducibility():
    set_seed(42)
    model1 = create_model()
    set_seed(42)
    model2 = create_model()
    # Check weights are identical
    for p1, p2 in zip(model1.parameters(), model2.parameters()):
        assert torch.allclose(p1, p2)`}
</CodeBlock>

## Checklist

Before submitting or sharing your work:

- [ ] Code is in version control (Git)
- [ ] Random seeds are set and documented
- [ ] Dependencies are specified
- [ ] Configuration files track all hyperparameters
- [ ] Data is versioned and accessible
- [ ] Results are logged and reproducible
- [ ] Documentation is complete
- [ ] Tests pass

## Conclusion

Reproducibility requires discipline but pays dividends in research quality and impact. Start with the basics: version control, seed management, and configuration files. Gradually add more sophisticated practices like experiment tracking and data versioning as your projects grow.

Remember that perfect reproducibility is an ideal to strive for. Document the limitations of your reproducibility efforts and be transparent about what others can and cannot expect to reproduce.
